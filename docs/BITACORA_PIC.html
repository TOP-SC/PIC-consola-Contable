Discovery (pedido real)

Problema declarado: falta de unificación de las bases del sistema operativo.

Objetivo: obtención de reportes mensuales y unificación para presentaciones impositivas.

Proceso actual: depende de recopilar datos en TXT → pasar a Excel → verificar y controlar → corregir TXT.

Dolor: datos erróneos y bases descentralizadas · liquidaciones quincenales y mensuales · riesgo de multas y reprocesos.

Test 3 preguntas (ticket): libera >5 h/semana = SI · datos 100% limpios/estructurados = NO (de ahí la necesidad del motor) · impacto económico directo = SI (multas fiscales). Decisión: APROBADO CON CONDICIONES.

Observaciones técnicas

  • Consola web PIC con splash, dashboard y sidebar modular (lista para más módulos contables).
  • Backend FastAPI: /api/search, /api/generate-download, /api/status, /api/health.
  • Lecturas SQL con NOLOCK + READ UNCOMMITTED para no trabar Tango.
  • Backend SQL portable vía pymssql (sin depender de ODBC en el RDS).
  • TXT IBPER de ancho fijo con “Guardar como” (el usuario elige destino).
  • Ejecutable portable + scripts ActualizarRDS / IniciarDesdeTR (WMI) sin tareas programadas ni cambios de configuración del RDS.
  • Anti-caché HTTP + versionado de assets (?v=2.0.2).
  • Marca de agua TOP en splash y pie de app.

Bitácora de edificación — Etapa 1

Relato de construcción desde cero, a partir del pedido Contable y del formato exigido por ARBA. Sin depender de un producto previo: relevamiento, diseño, desarrollo, empaquetado y puesta en red.

  • 04/08/2026 · Discovery
    Pedido Contable y definición del problema
    Ticket TOP-8FF105CB (Marcela Diaz): unificar bases descentralizadas para presentaciones impositivas. Se acota Etapa 1 a IBPER / percepciones IIBB Bs.As., el circuito más crítico y repetible (TXT → Excel → TXT).
  • 04/08/2026 · Discovery técnico
    Formato TXT ARBA y fuente Tango
    Se releva el layout de ancho fijo IBPER (CUIT, fechas, importes, alícuotas, signos de NC). Se identifica la consulta a la vista de impuestos y el SP de sucursales multinivel como fuente oficial en SQL Server / Tango. Primeros archivos del repo a las 17:31.
  • 04/08/2026 · Core backend
    FastAPI + motor IBPER + SQL
    Configuración, schemas, servicio SQL multi-sucursal, generación de bytes TXT, endpoints de búsqueda y descarga. Stack Python 3.12 + FastAPI + Pydantic.
  • 04/08 → 05/08 · Frontend v1
    Consola web operativa
    Pantalla de consulta por fechas, grilla unificada, estado de conexión, generación TXT. Validación de conectividad real a SQL Server desde el entorno con acceso a Tango.
  • 05/08/2026 · Portable
    PyInstaller + pymssql
    Ejecutable autónomo para RDS (sin instalar Python ni ODBC). Lecturas con NOLOCK. Decisión de arquitectura: app web local/portable, no RemoteApp ni cambios de config del servidor.
  • 05/08/2026 · Acceso remoto
    RDS + iniciador desde TR
    Escucha en 0.0.0.0:8787, scripts WMI para iniciar/actualizar sin tareas programadas (los RDS se reinician solos). Los usuarios abren la app por HTTP desde TR/local.
  • 05/08/2026 · Shell PIC
    Identidad de plataforma
    Renombre a PIC — Plataforma Integral Contable. Splash con fade, dashboard, sidebar modular, indicador de carga, “Guardar como”, tabla sin scroll horizontal, estado Conectado/Desconectado, marca de agua TOP.
  • 05/08/2026 · Cierre Etapa 1
    Repo + versión 2.0.2 en producción
    Publicación en GitHub TOP-SC/PIC-consola-Contable, anti-caché de assets, scripts de actualización remota validados. App viva en http://10.100.3.26:8787.

Decisiones de diseño

DecisiónPor qué
Web local portable (no WinForms / no RemoteApp) Acceso desde TR/local sin RDP al RDS · sin pedir permisos a otros sectores
pymssql + fallback pyodbc El RDS no puede depender de drivers ODBC preinstalados
NOLOCK / READ UNCOMMITTED Consultas de reporte sin bloquear operación de Tango
Eliminar Excel del camino crítico El Excel era el eslabón de error; la grilla + TXT directo es el camino correcto
Shell PIC multi-módulo desde el día 1 El ticket pide unificación amplia; IBPER es el primer módulo, no el último
Sin tareas programadas en RDS Restricción operativa: los RDS se reinician y no se pueden agendar tareas
